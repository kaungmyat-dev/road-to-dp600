# Microsoft Fabric Lakehouse မှတ်စုများ (Notes)

Microsoft Fabric ထဲက Lakehouse နဲ့ ပတ်သက်တဲ့ မှတ်စုများကို မြန်မာဘာသာသို့ အဆင်ပြေချောမွေ့စွာ ဖတ်ရှုလေ့လာနိုင်ရန် ပြန်ဆိုတည်းဖြတ်ထားခြင်း ဖြစ်သည်။

---

## ၁။ ဒါက ဘာလဲ။ (What is it?)
**Microsoft Fabric ထဲက Lakehouse** ဆိုတာ data lake ရဲ့ စိတ်ကြိုက်ပြောင်းလဲနိုင်ပြီး ပမာဏချဲ့ထွင်နိုင်တဲ့ သိုလှောင်မှုစနစ် (flexible, scalable storage) နဲ့ data warehouse ရဲ့ စီစစ်မေးမြန်းနိုင်တဲ့ စွမ်းဆောင်ရည်တွေ (analytical, queryable capabilities) ကို ပေါင်းစပ်ထားတဲ့ တစ်စုတစ်စည်းတည်းဖြစ်သော data platform တစ်ခု ဖြစ်ပါတယ်။ Data များကို လုပ်ဆောင်ဖို့နဲ့ ခွဲခြမ်းစိတ်ဖြာဖို့အတွက် Apache Spark နဲ့ SQL compute engine တွေကို အသုံးပြုထားပြီး OneLake storage layer ပေါ်မှာ တည်ဆောက်ထားတာ ဖြစ်ပါတယ်။

## ၂။ ဘာကြောင့် အရေးကြီးတာလဲ။ (What matters?)
Lakehouse ဟာ အဖွဲ့အစည်းတွေအတွက် raw data (အကြမ်းထည်ဒေတာ) ရော structured data (ပုံစံတကျဒေတာ) တွေကိုပါ တစ်နေရာတည်းမှာ သိမ်းဆည်းထားနိုင်စေပါတယ်။ ဒါကြောင့် ကုန်ကျစရိတ်သက်သာပြီး ပမာဏချဲ့ထွင်နိုင်တဲ့ storage အပြင် စိတ်ချရပြီး စွမ်းဆောင်ရည်မြင့်မားတဲ့ ခွဲခြမ်းစိတ်ဖြာမှု (analytics) တွေကိုပါ ရရှိစေမှာ ဖြစ်ပါတယ်။ 

၎င်းက ACID transactional tables (Delta Lake)၊ schema enforcement၊ time travel နဲ့ analytics tools တွေ (Power BI, SQL analytics endpoint, Spark notebooks) နဲ့ ချိတ်ဆက်လုပ်ဆောင်နိုင်မှုတို့ကို ပံ့ပိုးပေးထားသလို၊ layered security controls (အဆင့်ဆင့် လုံခြုံရေးထိန်းချုပ်မှုများ) လည်း ပါဝင်တာကြောင့် BI (Business Intelligence) ရော AI လုပ်ငန်းစဉ်တွေအတွက်ပါ လက်တွေ့ကျတဲ့ အခြေခံအုတ်မြစ်တစ်ခု ဖြစ်လာစေပါတယ်။

---

## ၃။ အဓိကအချက်များ (Key Points)

### အဓိက အယူအဆ (Core idea)
* **တစ်စုတစ်စည်းတည်းဖြစ်သော Platform (Unified platform):** data lake ရဲ့ သိမ်းဆည်းမှုဆိုင်ရာ စိတ်ကြိုက်ပြောင်းလဲနိုင်စွမ်းနဲ့ data warehouse ရဲ့ မေးမြန်း/ခွဲခြမ်းစိတ်ဖြာနိုင်စွမ်းတို့ကို ပေါင်းစပ်ပေးထားသည်။
* **Compute (တွက်ချက်မှုစနစ်):** Apache Spark နှင့် SQL engine များကို အသုံးပြုသည်။
* **Storage (သိုလှောင်မှုစနစ်):** OneLake ပေါ်တွင် တည်ဆောက်ထားသည်။

### Lakehouse ဖွဲ့စည်းပုံ (Lakehouse structure)
အဓိက အပိုင်း နှစ်ပိုင်းရှိသည် -
* **Tables (ဇယားများ)**
    * ပုံစံတကျရှိပြီး ရှာဖွေစစ်ဆေးနိုင်သော ဒေတာများ ဖြစ်သည် (Delta Lake tables)။
    * SQL analytics endpoint မှတစ်ဆင့် SQL queries များကို ပံ့ပိုးပေးသည်။
    * Schemas များကို အတည်ပြုသတ်မှတ်ပေးပြီး ACID transactions များကို ပံ့ပိုးပေးသည်။
    * Reporting လုပ်ရန်အတွက် Power BI မှတစ်ဆင့် ဝင်ရောက်အသုံးပြုနိုင်သည်။
    * အလိုအလျောက် ပိုမိုကောင်းမွန်အောင် ပြုပြင်ပေးခြင်း (automatic optimization) နှင့် ထိန်းသိမ်းခြင်းဆိုင်ရာ အကျိုးကျေးဇူးများကို ရရှိစေသည်။
* **Files (ဖိုင်များ)**
    * မူရင်း format များ (CSV, JSON, Parquet, ပုံများ၊ စာရွက်စာတမ်းများ) အတိုင်း သိမ်းဆည်းထားသော အကြမ်းထည် (raw) သို့မဟုတ် semi-structured ဒေတာများ ဖြစ်သည်။
    * ရှာဖွေလေ့လာရန်နှင့် လုပ်ဆောင်ရန်အတွက် လိုက်လျောညီထွေမှုရှိသည်။ Tables အဖြစ် မပြောင်းလဲမီ ပထမအဆင့် (staged) အနေဖြင့် ထားရှိနိုင်သည်။
    * Schema သတ်မှတ်ချက်များကို အတင်းအကြပ် မလုပ်ဆောင်သလို၊ တိုက်ရိုက် SQL queries များကိုလည်း ပံ့ပိုးမပေးပါ။

> **မှတ်ချက်:** ဤပုံစံဒီဇိုင်းသည် လိုက်နာရမည့် စည်းကမ်းချက်များ (compliance) သို့မဟုတ် ပြန်လည်လုပ်ဆောင်ရန် (reprocessing) အတွက် raw data များကို မပျက်မကွက် ထိန်းသိမ်းပေးထားပြီး၊ တစ်ဖက်တွင်လည်း ခွဲခြမ်းစိတ်ဖြာမှုအတွက် structured tables များကို ပံ့ပိုးပေးသည်။

### Delta Lake (Lakehouse ရဲ့ နှလုံးသား)
Data lakes များကို ပိုမိုစိတ်ချရမှု ရှိလာအောင် လုပ်ဆောင်ပေးသည့် Open-source storage layer ဖြစ်သည်။
* **အဓိက အားသာချက်များ:**
    * **ACID transactions:** အသုံးပြုသူ အများအပြား တစ်ပြိုင်နက် အသုံးပြုနေချိန်တွင်လည်း ဒေတာ ဖတ်ခြင်း/ရေးခြင်းများကို တသမတ်တည်း (consistent) ဖြစ်စေသည်။
    * **Schema enforcement:** ပျက်စီးနေသော သို့မဟုတ် ပုံစံမတူညီသော ဒေတာများ ဝင်ရောက်လာခြင်းမှ ကာကွယ်ပေးသည်။
    * **Time travel:** Transaction log ကြောင့် ယခင်က ရှိခဲ့ဖူးသော ဒေတာ version များကို ပြန်လည်ကြည့်ရှုနိုင်ခြင်း သို့မဟုတ် ပြောင်းလဲမှုများကို ယခင်အခြေအနေသို့ ပြန်ပြင်နိုင်ခြင်း (rolling back) တို့ကို လုပ်ဆောင်နိုင်သည်။
    * ထိရောက်မြန်ဆန်သော updates နှင့် deletes ပြုလုပ်မှုများကို ပံ့ပိုးပေးသည်။

### လုံခြုံရေးနှင့် ဝင်ရောက်အသုံးပြုမှု ထိန်းချုပ်ခြင်း (Security and access control)
* Fabric သည် အဆင့်ဆင့်ရှိသော ဝင်ရောက်ခွင့် ထိန်းချုပ်မှုများ (workspace roles၊ item-level sharing) ကို ပံ့ပိုးပေးသည်။
* SQL analytics endpoint သည် အသေးစိတ် ထိန်းချုပ်နိုင်ရန်အတွက် row-level နှင့် column-level လုံခြုံရေးစနစ်များကို ပံ့ပိုးပေးသည်။
* Tables များကို schemas များအဖြစ် စနစ်တကျ ဖွဲ့စည်းထားပါက Schema-level permissions (ခွင့်ပြုချက်များ) သတ်မှတ်နိုင်သည်။
* ရှင်းလင်းသော schemas၊ အမည်ပေးစနစ် (naming conventions) နှင့် အဓိပ္ပာယ်ဖော်ပြချက်ပါဝင်သော columns များဖြင့် စနစ်တကျ ဖွဲ့စည်းထားသည့် ဒေတာများသည် လူကိုယ်တိုင် ခွဲခြမ်းစိတ်ဖြာမှုများရော AI tools များ (ဥပမာ - Fabric IQ) ကိုပါ ကောင်းမွန်စွာ ပံ့ပိုးပေးနိုင်သည်။

### Lakehouse က Analytics နှင့် AI ကို ဘယ်လို ပံ့ပိုးပေးသလဲ
* သန့်စင်ပြီး မှတ်တမ်းအချက်အလက် ပြည့်စုံသော (documented) tables များသည် ပိုမိုကောင်းမွန်သည့် BI reporting နှင့် AI queries များကို ဖြစ်စေသည်။
* Fabric IQ data agents များသည် SQL analytics endpoint မှတစ်ဆင့် လူသားတို့ပြောဆိုသော သဘာဝဘာသာစကား (natural language) ကို Lakehouse tables များအတွက် SQL အဖြစ်သို့ ပြောင်းလဲပေးနိုင်သည်။

---

## ၄။ Lakehouses များ တည်ဆောက်ခြင်းနှင့် ဖွဲ့စည်းခြင်း (Creating and organizing)
* Schemas များကို default အနေဖြင့် ထည့်သွင်းပေးထားသည် (dbo schema)။ ယုတ္တိတန်တန် စုစည်းမှုများ ပြုလုပ်ရန်အတွက် (ဥပမာ - it, marketing စသည်ဖြင့်) နောက်ထပ် schemas များကို ထပ်မံတည်ဆောက်နိုင်သည်။
* Schema အသုံးပြုနိုင်သော lakehouses များသည် schema-level permissions များနှင့် workspace အချင်းချင်းကြား ကူးလူးမေးမြန်းမှုများ (cross-workspace queries) ကို `workspace.lakehouse.schema.table` ဟူသော namespace ပုံစံဖြင့် ပံ့ပိုးပေးသည်။

### အပြန်အလှန် အသုံးပြုနိုင်သည့် ပုံစံများ (Modes of interaction)
* **Lakehouse Explorer (explore mode):** ဒေတာများကို စီမံခန့်ခွဲခြင်း၊ files များ တင်ခြင်း (upload)၊ tables များ တည်ဆောက်ခြင်းနှင့် lakehouse ကို ပြုပြင်ပြောင်းလဲမှုများ ပြုလုပ်ခြင်းတို့ကို ဆောင်ရွက်နိုင်သည်။
* **SQL Analytics Endpoints (ဒေတာများအတွက် ဖတ်ရုံသာ - read-only):** T-SQL ကို အသုံးပြုပြီး Delta tables များကို query လုပ်နိုင်ခြင်း၊ views/functions များ တည်ဆောက်နိုင်ခြင်း၊ SQL security သတ်မှတ်နိုင်ခြင်းတို့ကို ပြုလုပ်နိုင်သော်လည်း ဤ endpoint မှတစ်ဆင့် အခြေခံဒေတာ (underlying data) ကို ပြုပြင်မွမ်းမံ၍ မရပါ။

---

## ၅။ ဒေတာများကို ထည့်သွင်းခြင်း (Ingesting data - ETL ရဲ့ ပထမဆုံးအဆင့်)
Lakehouse ထဲသို့ ဒေတာများ ထည့်သွင်းနိုင်သည့် နည်းလမ်းများမှာ -
* **Upload:** Lakehouse explorer မှတစ်ဆင့် မိမိစက်ထဲရှိ files/folders များကို တင်နိုင်သည်။
* **Load to Table:** Code ရေးရန်မလိုဘဲ Delta tables များ တည်ဆောက်ရန် file/folder ကို ရွေးချယ်ပြီး "Load to Table" ကို နှိပ်ရုံဖြင့် လုပ်ဆောင်နိုင်သည်။ (Parquet နှင့် CSV ကို ပံ့ပိုးပေးပြီး append သို့မဟုတ် overwrite လုပ်ရန် ရွေးချယ်ခွင့်များ ပါဝင်သည်)။
* **Dataflows Gen2:** Power Query မှတစ်ဆင့် ဒေတာများကို တင်သွင်းခြင်းနှင့် ပုံစံပြောင်းလဲခြင်းများ ပြုလုပ်နိုင်သည်။ (Power BI နှင့် Excel အသုံးပြုသူများအတွက် အလွန်အဆင်ပြေသည်)။
* **Notebooks:** ကုဒ်ရေးသားပြီး (programmatically) ထည့်သွင်းခြင်း၊ ပုံစံပြောင်းလဲခြင်းနှင့် load လုပ်ခြင်းများအတွက် Apache Spark (PySpark, SQL, Scala) ကို အသုံးပြုသည်။
* **Data Factory Pipelines:** ပြင်ပရင်းမြစ်များမှ ဒေတာများကို ရွှေ့ပြောင်းရန် "Copy Data" activity ကို အသုံးပြုသည်။

**Shortcuts နှင့် ခွင့်ပြုချက်များ (permissions):**
* OneLake shortcut မှတစ်ဆင့် ဒေတာများကို ဝင်ရောက်အသုံးပြုခြင်းသည် သင့်အကောင့် (identity) ကို အသုံးပြု၍ ခွင့်ပြုချက်တောင်းခံခြင်းဖြစ်သောကြောင့် သွားမည့်နေရာ (target location) တွင် သင့်၌ ဝင်ရောက်ခွင့် (permission) ရှိရပါမည်။
* Schema shortcuts များသည် target table မှ schemas တစ်ခုလုံးကို ချက်ဆက်ပေးသဖြင့် ညွှန်းဆိုထားသော tables များသည် schema အတွင်းရှိ local tables များကဲ့သို့ ပေါ်လာမည်ဖြစ်သည်။

---

## ၆။ ဒေတာများကို ပုံစံပြောင်းလဲခြင်း (Transforming data)
ပုံစံပြောင်းလဲခြင်း (Transformation) အတွက် အသုံးပြုနိုင်သော Tools များ -
* **Notebooks (PySpark, SQL, Scala):** ကုဒ်ရေးသားပြီး လုပ်ဆောင်ရမည့် ပုံစံပြောင်းလဲမှုများနှင့် ရှုပ်ထွေးသော logic များအတွက် အသုံးပြုသည်။
* **Dataflows Gen2 (Power Query):** Power BI အသုံးပြုသူများ ရင်းနှီးပြီးသားဖြစ်သော အသုံးပြုရလွယ်ကူသည့် ပုံစံပြောင်းလဲမှုများအတွက် အသုံးပြုသည်။
* **Pipelines (visual orchestration):** ETL လုပ်ငန်းစဉ်များကို အစီအစဉ်တကျ (in order) သို့မဟုတ် တစ်ပြိုင်နက်တည်း (parallel) အလုပ်လုပ်စေရန် အသုံးပြုသည်။

**အသုံးပြုသည့် ပုံစံများ (Use cases):**
* Raw files များကို ပထမအဆင့် သိမ်းဆည်းခြင်း (Stage)၊ ထို့နောက် Delta tables များအဖြစ် ပြောင်းလဲခြင်း၊ ပြီးလျှင် ခွဲခြမ်းစိတ်ဖြာမှုအတွက် tables များကို ပိုမိုကောင်းမွန်အောင် ပြုပြင်ထိန်းသိမ်းခြင်း။

---

## ၇။ Lakehouse Data များကို မေးမြန်းခြင်းနှင့် ခွဲခြမ်းစိတ်ဖြာခြင်း (Querying and analyzing)

### SQL Analytics Endpoint
* အရေးပေါ် စစ်ဆေးမှုများ (ad-hoc investigation)၊ BI ချိတ်ဆက်မှုများ (Power BI, Excel, Azure Data Studio) နှင့် ဒေတာမှန်ကန်မှု စစ်ဆေးခြင်း (data validation) တို့အတွက် အသုံးပြုသည်။
* ထပ်ခါတလဲလဲ ပြန်လည်အသုံးပြုနိုင်မည့် logic များကို သိမ်းဆည်းရန် SQL views များ တည်ဆောက်နိုင်သည်။
* Row-level နှင့် column-level လုံခြုံရေးစနစ်များကို ပံ့ပိုးပေးသည်။

### Spark Notebooks
* Query လုပ်ရန်နှင့် ခွဲမ်းစိတ်ဖြာရန်အတွက် လိုက်လျောညီထွေရှိသော code-based ပတ်ဝန်းကျင်တစ်ခု ဖြစ်သည်။
* ပုံစံပြောင်းလဲခြင်းနှင့် ကိုင်တွယ်အသုံးပြုခြင်းများအတွက် Spark SQL cells များ (ဥပမာ - `SELECT * FROM schema.table`) နှင့် PySpark ကို အသုံးပြုသည်။
* **အများဆုံး အသုံးပြုသည့် ပုံစံများ:** အစောပိုင်း ဒေတာဆန်းစစ်ခြင်း (exploratory data analysis)၊ ရှုပ်ထွေးသော ပုံစံပြောင်းလဲမှုများ၊ workspace အချင်းချင်းကြား ကူးလူးမေးမြန်းမှုများ (four-part namespace: `workspace.lakehouse.schema.table`)။

### Power BI နှင့် ချိတ်ဆက်အသုံးပြုခြင်း (Power BI integration)
* ချိတ်ဆက်မှု နည်းလမ်း နှစ်မျိုးရှိပြီး အဓိကနည်းလမ်းမှာ SQL analytics endpoint ဖြစ်သည်။
* Lakehouse tables များကို ညွှန်းဆိုသည့် semantic model (ဆက်ဆံရေးများ - relationships၊ measures၊ business logic များ) ကို တည်ဆောက်နိုင်သည်။
* **Direct Lake mode (default):** ဒေတာများကို import လုပ်ရန်မလိုဘဲ Lakehouse ထံမှ တိုက်ရိုက်ဖတ်ရှုသဖြင့် လျင်မြန်သော queries များနှင့် နောက်ဆုံးပေါ် ဒေတာရလဒ်များကို ရရှိစေသည်။

---

## ၈။ Data ပညာရှင်များအတွက် လက်တွေ့ကျသော အကျိုးကျေးဇူးများ (နေ့စဉ်လုပ်ငန်းခွင်မှာ ဘယ်လိုအရေးပါသလဲ)
* **မှန်ကန်သော ဒေတာရင်းမြစ်တစ်ခုတည်းဖြစ်ခြင်း (Single source of truth):** Raw files များနှင့် စနစ်တကျ ပြင်ဆင်ထားသော curated tables များသည် တစ်နေရာတည်းမှာ အတူတကွ တည်ရှိနေသည်။
* **ထပ်ခါတလဲလဲ ဖြစ်ခြင်းကို လျှော့ချနိုင်ခြင်း (Reduced duplication):** Direct Lake ကြောင့် ဒေတာများကို BI အတွက် သီးခြားစီ ထပ်ခါတလဲလဲ ကူးယူသိမ်းဆည်းနေစရာ မလိုတော့ပါ။
* **စမ်းသပ်မှုများကို ပိုမိုမြန်ဆန်စေခြင်း (Faster experimentation):** Notebooks နှင့် Delta tables များပေါင်းစပ်မှုသည် data engineers များနှင့် analysts များကို လုပ်ငန်းစဉ်များ လျင်မြန်စွာ ထပ်ခါတလဲလဲ စမ်းသပ်လုပ်ဆောင်နိုင်စေသည်။
* **ကြီးကြပ်မှုနှင့် စည်းကမ်းလိုက်နာမှု (Governance and compliance):** Schema enforcement၊ time travel နှင့် အဆင့်ဆင့်ရှိသော လုံခြုံရေးစနစ်များသည် ဒေတာစစ်ဆေးခြင်း (auditing) နှင့် ထိန်းချုပ်ဝင်ရောက်ခွင့်တို့ကို ကောင်းမွန်စွာ ပံ့ပိုးပေးသည်။

---

## ၉။ ဥပမာ သရုပ်ဖော်ချက် (အကျဉ်းချုပ်)
**ပုံမှန် အလုပ်လုပ်ပုံအဆင့်ဆင့် (Typical flow):**
1. Raw logs (JSON) များကို lakehouse files ထဲသို့ တင်ခြင်း (Upload)။
2. Schema ပါဝင်သော Delta table ထဲသို့ ပြောင်းလဲသတ်မှတ်ပြီး ထည့်သွင်းရန် Notebook သို့မဟုတ် Dataflows Gen2 ကို အသုံးပြုခြင်း။
3. Schema-level permissions များ သတ်မှတ်ပြီး စီးပွားရေးလုပ်ငန်းသုံးသူများအတွက် SQL view တစ်ခု တည်ဆောက်ခြင်း။
4. အချိန်နဲ့တပြေးညီ အစီရင်ခံစာများ (live reports) ရရှိရန်အတွက် Power BI ကို Direct Lake mode ဖြင့် SQL analytics endpoint သို့ ချိတ်ဆက်ခြင်း။
